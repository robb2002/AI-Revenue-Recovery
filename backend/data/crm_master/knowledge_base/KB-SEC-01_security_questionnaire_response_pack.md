# Security Questionnaire Response Pack

Illustrative document, SYNTHETIC. It explains how a security questionnaire is handled and what a representative may answer alone. Public statements are in KB-OFF-04, KB-OFF-05, and KB-OFF-06.

## Purpose
Customers, especially public bodies and universities, send security questionnaires before they buy. This pack sets out who answers what.

## What a representative can answer
- General statements that are quoted from the public security overview (KB-OFF-04), with the source link.
- That the questionnaire has been received and passed to the security team.
- The expected process and the owner, but not a date unless the security team has given one.

## What must go to the security team
- Any question about a certification held by a named product.
- Audit reports, penetration test summaries, and vulnerability handling.
- Hosting location, backup, disaster recovery, and retention for a named product.
- Sub-processors and data flows.
- Incident notification terms.

## Standard handling steps
1. Log the questionnaire against the opportunity with the received date and the customer deadline.
2. Send it to Information Security with the product names and the customer's country.
3. The security team returns answers or a request for clarification.
4. The representative sends the answers only after the security team approves them.
5. Record any customer follow-up questions as new items.

## Wording guide
| Customer asks | Safe wording |
|---|---|
| Are you SOC 2 certified? | The public security overview says controls support compliance with a list of frameworks where applicable. Product-specific reports come from the security team. |
| Where is our data stored? | It depends on the product. I will confirm for the product you are considering. |
| Do you encrypt data? | The public security overview says data is encrypted at rest and in transit. |

## Not stated in this pack
- Certification dates, report availability, and recovery targets.
- Any commitment on incident notification times.
